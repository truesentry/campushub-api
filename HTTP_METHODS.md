# HTTP-методи для API подій

| Метод | Призначення в API | Безпечний | Ідемпотентний | Успішний статус |
| --- | --- | --- | --- | --- |
| GET | Отримати список, відфільтрований за `?date=...`, або одну подію за `/:id` | Так | Так | `200 OK` |
| POST | Створити нову подію | Ні | Ні: кожний виклик створює іншу подію | `201 Created` |
| PUT | Повністю замінити назву й дату події за `/:id` | Ні | Так: однаковий запит залишає однаковий результат | `200 OK` |
| PATCH | Змінити лише передані поля події за `/:id` | Ні | Так для однакового набору значень | `200 OK` |
| DELETE | Видалити подію за `/:id` | Ні | Так: після першого успішного видалення події вже немає | `204 No Content` |

## Типові відповіді

- `400 Bad Request` — некоректний JSON або дані (наприклад, дата не у форматі `YYYY-MM-DD`).
- `404 Not Found` — події за вказаним `id` не існує.
- `500 Internal Server Error` — файл подій не прочитано або не збережено. Технічні деталі лишаються в консолі сервера.

Для JSON-відповідей сервер встановлює `Content-Type: application/json; charset=utf-8`. Успішний `DELETE` повертає `204` без тіла і без `Content-Type` — це очікувана HTTP-поведінка.
